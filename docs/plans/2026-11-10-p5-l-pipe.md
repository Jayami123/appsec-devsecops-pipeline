## 5. Per-scanner specification

### 5.0 Workflow topology and skeleton

- `ci.yml` calls `p5-scans.yml` once per PR or push, with no inputs (`ci.yml:92-98`). Every `p5-scans` run therefore runs CodeQL, whatever the changed paths (`p5_codeql` is passed to the gate, not to the workflow). The gate judges CodeQL only when `p5_codeql=true` (`ci-gate.mjs:112-119`).
- Report-only jobs (`gitleaks-forks`, `osv-forks`, `trivy-images`, `trivy-forks`, `syft`) run only on `push` to `main`, on `workflow_dispatch`, and on a pull request whose diff touches `config/scan/` (owner decision, accepted; section 9, O-6). The `decide` job computes this from the diff (same method as `ci-changes.sh`).
- Expected cost of the report-only jobs when they run: image scans about 2.5 minutes (Trivy 7 s to 50 s per image; Syft 4 s to 33 s per image; probe 2d) plus about 3 GB of image layers and DB (probe 2f). The root gate jobs take about 1 minute.
- CodeQL on every call: the action downloads the 559 MB bundle each run unless its cache hits (probe 2f). Expected 2 to 3 minutes per run.

Skeleton (the build fills the step bodies; this fixes the shape, outputs and exit rule):

```yaml
name: p5-scans

on:
  workflow_call:
    outputs:
      codeql_verdict:
        description: "CodeQL verdict from the summary job"
        value: ${{ jobs.summary.outputs.codeql_verdict }}
      scanner_status:
        description: "comma list of name=verdict, one per registry key that is judged on this run"
        value: ${{ jobs.summary.outputs.scanner_status }}
  workflow_dispatch:

permissions:
  contents: read

jobs:
  decide:                                  # report-only policy (O-6)
    runs-on: ubuntu-latest
    timeout-minutes: 5
    outputs:
      report: ${{ steps.decide.outputs.report }}
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with: { fetch-depth: 0, persist-credentials: false }
      - id: decide
        run: bash scripts/scan/decide-report.sh >> "$GITHUB_OUTPUT"   # prints report=true|false

  gitleaks:                                # blocking, this repository
    runs-on: ubuntu-latest
    timeout-minutes: 20
    outputs:
      verdict: ${{ steps.verdict.outputs.verdict }}
    steps:
```

Rules this skeleton enforces:
- A computed `fail` is a job output and the step exits 0. Only a tool or infrastructure error exits non-zero (the `scan` step, `exit 1`).
- The `summary` job has `if: always()`. It turns every job that did not succeed into `fail` (section 5.9).
- `scanner_status` is `name=verdict` pairs joined by `,`, one pair per registry key, each exactly once; report-only keys may be `skipped` (section 5.9), and `codeql_verdict` equals the `codeql` pair (`ci-gate.mjs:82-104`).

### 5.9 Summary aggregator and registry map (P5-SCAN-005 and correction 7)

5. The output has one `name=verdict` pair per registry key (every registry key, exactly once), in registry order, joined by `,`. `codeql_verdict` is the `codeql` verdict.
6. The `summary` table row for a `skipped` key reads `SKIPPED (report-only, not run on this event)`.

### 5.12 TypeScript skeletons

`scripts/scan/threshold-core.ts` (skeleton; the build completes it and its tests):

```ts
// Verdict contract for every L-PIPE scanner (MP:763, MP:767-771).
export type Verdict = "pass" | "fail" | "not-implemented" | "skipped"; // "skipped" only for REPORT_ONLY_KEYS (section 5.9)
export type Severity = "CRITICAL" | "HIGH" | "MEDIUM" | "LOW" | "UNKNOWN";

export interface ScanOutcome {
  readonly verdict: Verdict;
  readonly reason: string;
  readonly blocking: readonly string[]; // fingerprints only; never message or match text
}

export function normalizeSeverity(raw: string | undefined): Severity {
  switch ((raw ?? "").toUpperCase()) {
    case "CRITICAL":
      return "CRITICAL";
    case "HIGH":
      return "HIGH";
    case "MEDIUM":
    case "MODERATE": // OSV says MODERATE; Trivy says MEDIUM (probe 2b)
      return "MEDIUM";
    case "LOW":
      return "LOW";
    default:
      return "UNKNOWN";
  }
}

export function failClosed(reason: string): ScanOutcome {
  return { verdict: "fail", reason, blocking: [] };
}

// An expired baseline or accepted-risk entry counts as NEW (MP:698).
export function isExpired(expiresIso: string, nowIso: string): boolean {
  return Date.parse(expiresIso) < Date.parse(nowIso);
}
```

`scripts/scan/codeql-threshold.ts` (skeleton; reads rule severity because SARIF `level` is absent, probe 2b):

```ts
import { readFileSync } from "node:fs";
import { failClosed, type ScanOutcome } from "./threshold-core.ts";

// D4 ownership (MP:696): only P5-owned paths block.
const OWNED_PREFIXES: readonly string[] = ["src/", "scripts/", "tests/", ".github/"];

interface SarifRule { properties?: { "security-severity"?: string } }
interface SarifResult {
  ruleId: string;
  ruleIndex: number;
  locations?: { physicalLocation?: { artifactLocation?: { uri?: string } } }[];
  partialFingerprints?: { primaryLocationLineHash?: string };
}
interface Sarif {
  runs?: {
    invocations?: { executionSuccessful?: boolean }[];
    tool: { driver: { rules: SarifRule[] } };
    results?: SarifResult[];
  }[];
}

export function evaluateCodeql(sarifPath: string, baseline: ReadonlySet<string>): ScanOutcome {
  let doc: Sarif;
  try {
    doc = JSON.parse(readFileSync(sarifPath, "utf8")) as Sarif;
  } catch {
    return failClosed("unreadable SARIF");
  }
  const run = doc.runs?.[0];
  if (!run || run.invocations?.[0]?.executionSuccessful !== true) {
    return failClosed("SARIF without a successful invocation");
  }
  const blocking: string[] = [];
  for (const result of run.results ?? []) {
    const sev = Number(run.tool.driver.rules[result.ruleIndex]?.properties?.["security-severity"]);
    const uri = result.locations?.[0]?.physicalLocation?.artifactLocation?.uri ?? "";
    const fp = `${result.ruleId}|${uri}|${result.partialFingerprints?.primaryLocationLineHash ?? ""}`;
    const owned = OWNED_PREFIXES.some((prefix) => uri.startsWith(prefix));
    if (sev >= 7.0 && owned && !baseline.has(fp)) blocking.push(fp); // High or Critical, NEW, owned
  }
  return blocking.length === 0
    ? { verdict: "pass", reason: "no NEW High or Critical in owned code", blocking }
    : { verdict: "fail", reason: "NEW High or Critical in owned code", blocking };
}
```

## 6. Threshold semantics (per tool)

Common rules:

1. The gate reads the tool's output file. A missing file, an unparseable file, a missing invocation, or an exit code outside the documented set is `fail` (NEW-PIPE-2).
2. A tool error in a report-only job is `fail`. Report-only means findings do not block.
3. `pass` requires that the output was parsed and every finding was classified.
4. Exit codes are documented per tool in section 5.13. A computed `fail` is a job output (section 5.0).

### 6.1 gitleaks (blocking, this repository)

- Exit 0 and parsed JSON with zero findings: `pass`. Exit 2 with parsed JSON and at least one finding: `fail`. Exit 1, or any other code: `fail`.
- Only the allowlist in `config/scan/gitleaks.toml` suppresses a finding. Accepted risks never suppress gitleaks (a secret is removed or allowlisted by line, not accepted).
- Fingerprint for review: `RuleID|File|StartLine` (the reduced artefact, section 5.2).

### 6.2 Trivy (root blocking; the rest report-only)

- Scope: `trivy fs --include-dev-deps` (required, probe 2h). Without the flag, dev-dependency advisories are missed.
- Fingerprint: `VulnerabilityID|PkgName|InstalledVersion|Target`.
- Owned: `Target` equals `package-lock.json`. This is the repository's own dependency tree. Fork and image targets are not owned.
- Fix available: `FixedVersion` is non-empty.
- Blocks when: NEW (not in `config/scan/baseline/trivy.json`, or its entry is expired) and owned and `Severity` is `HIGH` or `CRITICAL` and fix available.
- Current result on 5a3a1d9: one MEDIUM (`CVE-2026-118764`, minimatch, fixed 11.0.1). Not blocking. It is the same advisory as the npm and OSV results (6.4).

### 6.3 OSV-Scanner (root blocking; forks report-only)

- Fingerprint: `id|package.name|package.version|source.path`.
- Severity: `database_specific.severity`, normalised by `normalizeSeverity`. Missing or `UNSPECIFIED` is `UNKNOWN` (not blocking).
- Fix available: any `affected[].ranges[].events[]` with a `fixed` key for the matched package (probe 2a structure).
- Owned: `source.path` equals `package-lock.json`.
- Blocks when: NEW and owned and HIGH or CRITICAL and fix available.
- Current result: one MEDIUM (`GHSA-g3hv-75wg-m249`, fixed 11.0.1). Not blocking. OSV is the primary dependency gate.

### 6.4 npm audit (D5 cross-check; root only)

- Fingerprint: keyed on the advisory, not on the package. The advisory is the object in `via`: fingerprint `<advisory source id>|<range>`. Probe 2h: all ten `npm` entries trace to one advisory object (`source` 1244623, `range` `>=7.0.0 <11.0.1`, GHSA-g3hv-75wg-m249). Transitive entries are strings that point to a parent package; they are followed to the advisory object.
- Severity: from the advisory's `severity`.
- Fix available: `fixAvailable` is truthy. A `fixAvailable` object with `isSemVerMajor: true` counts as fix available and is labelled in the summary (probe 2c: all seven object fixes on 298ae29 are major and propose older versions).
- Owned: the root `package-lock.json`.
- Blocks when: NEW and owned and HIGH or CRITICAL and fix available.
- Current result: 10 moderate, all dev-only, one advisory. Not blocking. Still open; not accepted; no accepted-risk entry.

### 6.5 CodeQL (PN-4; MP:693-700)

- Severity: `rules[ruleIndex].properties["security-severity"]`. Critical at 9.0 or above; High at 7.0 or above. The SARIF `level` is absent on CodeQL results (probe 2b), so `level` is not used.
- Newness: fingerprint `ruleId|uri|partialFingerprints.primaryLocationLineHash` not in `config/scan/baseline/codeql.json` (or entry expired).
- Ownership: `uri` starts with `src/`, `scripts/`, `tests/` or `.github/` (MP:696).
- Fix available: true by definition for owned code (MP:697; correction 12).
- Accepted risks: suppressed only by an unexpired `accepted_risks` entry whose `match.fingerprint` and `match.tool` (`codeql`) match (section 7.4).
- Verdict: `fail` if any NEW, owned, High or Critical result remains. Upload success is never the gate (MP:699).
- Result on main (5a3a1d9): two High alerts (probe 2c). After F0-5a (section 5.5.1): zero.

### 6.6 zizmor (PN-6; blocking on errors)

- Blocks when any SARIF result has `level` `error`. Warnings and notes are reported, not blocking.
- Exit code is not used for the verdict (exit 0 with findings, RECORDED-2). Exit 1 or 3 is `fail` (3 means no inputs; a workflow directory with no workflows is `fail`).
- Result on 5a3a1d9: 13 results (5 warnings, 8 notes), 0 errors. Pass.

### 6.7 ZAP (report-only; D11)

- `pass` when the baseline ran, produced parseable JSON, and the stack was torn down. `fail` on crash, timeout, malformed or missing JSON, or a stack that did not stop.
- Alerts never change the verdict. High and above are written to the summary. A finding becomes a `findings[]` entry only by owner decision (MP:611 and the ledger rules).
- Authenticated mode: not implemented until the login helper merges (MP:337).

### 6.8 syft and summary

- Syft: section 5.7.
- Summary: section 5.9. It has no verdict of its own. A missing scanner row is `fail`.

### 6.9 Gate reading (F0-3 contract, MP:681) and registry flips (MP:765, MP:768, MP:770)

- `codeql_verdict` and `scanner_status` are written by the `summary` job (section 5.9).
- `scanner_status` is a comma list of `name=verdict` pairs. Each pair name is a registry key, and each key appears exactly once. The `codeql` pair equals `codeql_verdict` (`ci-gate.mjs:82-104`).
- The gate fails when a key with registry value `implemented` reports `not-implemented`, when any value is `fail`, or when a `stub` key reports `pass` or `fail` (MP:770, rejected by `registry.test.ts`). A `stub` key reporting `not-implemented` passes with a `NOT IMPLEMENTED` row (MP:768).
- Correction 17 and O-15: `zap` and `syft` are report-only. They report `skipped` when their job did not run; they are never absent. The gate accepts `skipped` only for `REPORT_ONLY_KEYS = [syft, zap]`, and only when the registry says `implemented`. Every other registry key must be present with `pass` or `fail` (or `not-implemented` while a stub). F0-5b (e).
- Registry flip: each implementing PR changes its own key in `config/scan/implementation-status.json` from `stub` to `implemented` in the same PR (MP:765). The registry test fails if the job is missing or if a stub marker remains on `p5-scans.yml` while `scripts/scan/` has files.

## 7. Baseline, accepted risks, enforcement

### 7.1 Baseline format (correction 6)

Path: `config/scan/baseline/<tool>.json` for `codeql`, `trivy`, `osv` and `npm-audit`. Schema (validated by `tests/unit/scan/baseline.test.ts`):

```json
{
  "schema": 1,
  "tool": "codeql",
  "entries": [
    {
      "fingerprint": "js/regex/missing-regexp-anchor|tests/unit/kit/import-closure.test.ts|<primaryLocationLineHash>",
      "ruleId": "js/regex/missing-regexp-anchor",
      "path": "tests/unit/kit/import-closure.test.ts",
      "justification": "<one sentence: why the result is a false positive or accepted as known>",
      "owner": "the owner",
      "reviewRef": "<owner review reference on the PR>",
      "addedOn": "YYYY-MM-DD",
      "expires": "YYYY-MM-DD"
    }
  ]
}
```

Rules:
- `expires` at most 90 days after `addedOn` (MP:671). The test rejects longer.
- An expired entry is NEW.
- An entry that matches no current result is stale. Stale = `fail` for that tool until the entry is removed in the same PR that fixed the alert (NEW-PIPE-3).
- `owner` is a role ("the owner"), never a personal name (MP:616).
- Initial state: `trivy`, `osv` and `npm-audit` start empty (no owned High or Critical with a fix on main). `codeql` starts empty after F0-5a.

### 7.2 Baseline change review

- Each baseline change is its own PR (correction 3). Builders do not approve their own baseline change.
- Owner review on `config/scan/baseline/` is an owner action (O-5), because the code cannot prove reviewer identity.
- Tampering control: a PR that adds an entry without the fields fails `baseline.test.ts`. An entry with all fields but no owner review is a process failure the owner catches at review (stated limit, 7.3).

### 7.3 Enforcement limit

Nothing in the code proves that a reviewer approved a baseline line. The plan relies on the owner's review, the field checks, and the same-PR stale rule. This is a stated limit, not a control.

### 7.4 Accepted risks (F0-4 ledger, extended in F0-5b (c))

- Current fields (`docs/findings/ledger.schema.json:84-99`): `id`, `product`, `status: "accepted-risk"`, `title`, `severity`, `owner`, `reason`, `acceptedOn`, `expires`.
- Added in F0-5b (c): `match: { tool: <registry key enum>, fingerprint: <string> }`, required. The schema alone cannot compare dates, so `src/security/accepted-risk.ts` validates these:
  - `expires` is after `acceptedOn`;
  - `expires` is at most `acceptedOn` + 90 days (`ACCEPTED_RISK_TTL_DAYS`, MP:671).
  Schema validation runs in `ledger.test.ts`; the date rules run in `tests/unit/security/accepted-risk.test.ts`.
- Expired entries fail the gate (MP:611, MP:698). An entry with no match suppresses nothing.
- `accepted_risks` stays `[]` until the owner approves an entry (O-4). When the first real entry is added, `tests/unit/docs/ledger.test.ts:87-89` changes with owner approval (O-4a).

### 7.5 Fork PRs (correction 9)

Recorded decision: fail-closed by design.

- On a fork PR, `p5-scans` is skipped by its same-repo `if:` (`ci.yml:94`). The gate sees a skipped scan job while `p5_scans` is true and fails (`ci-gate.mjs:74-77`).
- A fork PR cannot merge until the owner decides otherwise. This is the safe default.
- Option A (default): no change.
- Option B: a `gitleaks` job on `pull_request` outside the same-repo condition, with `permissions: contents: read`, no `secrets:`, and `persist-credentials: false`. It blocks a synthetic secret in a fork PR. It is a foundation `ci.yml` change needing its own foundation PR. `pull_request_target` is not used (9.11 test 6, MP:740; GitHub's warning, probe 2e).
- NEW-PIPE-6 covers the chosen option. The fork-PR behaviour is an owner check after the gate exists (O-7).
