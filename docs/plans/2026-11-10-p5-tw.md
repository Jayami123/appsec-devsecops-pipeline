## 6. Row specifications

Rules that apply to every row:
1. **Setup.** Throwaway actors only, created with the run prefix from `src/kit/run/prefix.ts` (`currentRunPrefix`, `runScopedName`). No seed user, no copied credential (MP:350; section 16 line 904).
2. **Control first.** The independent valid control runs before the negative, with the same actor and resource class (MP section 16, line 903).
3. **Negative.** One negative per fixture. Mutations have their own fixtures (MP:349).
4. **Before and after state** is read for every mutation.
5. **Oracle.** Named in each row.
6. **Budget.** Only by name from `BUDGETS` (`src/security/budgets.ts`). No bare number.
7. **Cleanup in `finally`.** `runAllThenRethrow` (`src/kit/shared/cleanup.ts`), then `sweepAfterTest` (`src/kit/invariants/after-test.ts`), then revoke every key or token before the harness is torn down (MP:354).
8. **Gated rows** have no test file until the gate lifts. No `.skip`, `.only` or `test.fail` (MP section 16, line 902 allows `test.fail` only for a proven public product defect, with a bug ID).
9. **Route names** marked `ROUTE(P-4)` are not confirmed. They are filled in only after the live probe runs. Until then the row is UNPROBED.
10. **Limiter readback before any limiter oracle.** Before an oracle relies on a forwarded limiter value (3a-2, P-9, GQL-004 / `TW_LIMITER_LAYERS`, RL-001, RL-002), read the **effective** window back from the running stack: the Redis key period suffix, or the 429 response. A mismatch between the forwarded value and the effective window is an **ENVIRONMENT** finding, never a product result. (The owner's observation of `:-:60` against `3600000` is UNVERIFIED; the cause is UNCONFIRMED.)
