## 5. Per-row design

Every row follows the same order: setup; the independent valid control, executed first (the task rule: control and negative share the actor and resource class; the phrase is not in the master plan); the negative step; before and after state where state changes; the oracle; the named budget (no bare numbers); cleanup in `finally`; the expected verdict type; the exact test names.

Every probe actor is a throwaway created per run with the `p5-qa-` prefix, through a normal product route. Every created token or API key is revoked before `down`. Every stack ends with `down` in an `if: always()` step. No seed user is used. Neither product's Stripe live mode is used: the export path does not touch Stripe.

### 5.0 Corpus contract (proposal; L-CAL's module is not on main)

The X build re-checks these names against the merged `src/lanes/cal/csv-corpus.ts`. Any difference is a STOP.

- `export const CSV_CORPUS: readonly { id: string; cell: string; kind: "plain" | "formula" | "numeric-formula" | "space-formula" }[]`
- `export function isFormulaLike(cell: string): boolean` (true when the first character is `=`, `+`, `-`, `@`, TAB or CR).
- Plain controls start with an ASCII letter and contain no formula character at position 0 or after leading whitespace.
- Formula cells start with `=`, `+`, `-`, `@`, TAB or CR (`fork ref held by the owner`).
- Numeric-formula cells are numeric-looking, such as `-5` or `+1`. Medusa exempts these (`fork ref held by the owner`).
- Space-formula cells are one space or TAB followed by a formula character. Medusa strips them (`fork ref held by the owner`); Twenty does not match them (`fork ref held by the owner`).
- Corpus size is a committed count. It has no budget.
- The run prefix goes into the record or product name, never into a corpus cell, so the corpus stays a fixed literal set.
