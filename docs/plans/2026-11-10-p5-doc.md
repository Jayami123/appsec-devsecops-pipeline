## 4. Row specifications

Every row below gives: setup, the independent valid control (run first, same actor and resource class, MP:916, the verdict-type rule at 298ae29), the negative step, before and after state, the oracle, the named budget, cleanup in `finally`, the verdict type, the exact test names, and a skeleton.

Shared rules for every row (MP:354, AGENTS.md "Failure classification and test rules"):
- Actors are throwaway, created per run with the `p5-qa-` run prefix through a product route (section 6.1). Never a seed user.
- Every negative check has its own fixtures and runs after its control. A control never changes the state a negative reads.
- `test.fail` is not used by any L-DOC row. A proven product defect is recorded as `PRODUCT BUG (SUSPECTED)` with evidence, and a `test.fail` is added only after a proof (AGENTS.md).
- No timeout raise, retry, skip or sleep. Async waits use `expect.poll` with a named deadline.
- Cleanup runs in `finally`. Each row sweeps its own envelopes, templates and sessions, then the job runs a leak check. Auth tokens and API keys created by a run are revoked before `down`.
