## 8. Per-row specification

### 8.0 Rules that apply to every row

1. **Budgets by name only.** Import from `src/security/budgets.ts` (`BUDGETS.<NAME>.value`). No bare number in any spec.
2. **Run prefix.** `currentRunPrefix()` from `src/kit/run/prefix.ts`. Every actor, function and key name carries the prefix (MP:493).
3. **Control first, same actor and resource class.** Every negative check is preceded by an independent valid control that uses the same actor and resource class (MP:903, section 16). A "blocked" result without a passing control is **not** evidence (probe A5: the disabled driver throws for every call).
4. **Limiter.** Each actor's requests stay within the short layer named in `TW_LIMITER_LAYERS`. No row exhausts a layer. GQL-004 is the only row that changes a limiter, and it runs last (section 9).
5. **Limiter readback.** Every oracle that depends on a limiter value first reads the effective value (X-10, `effective-config.ts`). A mismatch is an ENV finding.
6. **Verdicts.** `PASS`, `design verdict`, `PRODUCT BUG (SUSPECTED)`, `TEST BUG`, `ENV` or `gated` (MP:935). A design-verdict row asserts its control and records the observed behaviour as a test annotation; it does not assert a security value. A test that cannot prove its property at its budget reports a gated status or a finding, never PASS (MP section 8 rule).
7. **Cleanup in `finally`.** Delete the function or record created by the test, call `revokeAll()`, then run the leak sweep (`src/kit/invariants/after-test.ts`, merged F0-2).
8. **Redaction.** No secret, token, cookie or canary value is printed or stored. Canary values are never written to disk and never logged (probe B2, `twenty-canary.ts:44-46`).
9. **Gated rows.** No spec file (X-3). The skeletons below are design text for the build after the gate. They are not files.

### 8.1 P5-TW-SND-001 (gated)

- **Gate:** harness item 1 and the canary pass-through (both delivered in `v0.4.0`); pin bump to `v0.4.0`; D8 (MP:78); D-P12 (parent-side presence check via the named-canary route, section 6); live Docker.
- **Setup (after the gate):** `LOGIC_FUNCTION_TYPE=LOCAL` (value validated at `twenty-runtime-override.ts:66-81`); `HARNESS_TWENTY_CANARY_NAME` set to `P5_CANARY_<RUN_ID_UPPER>` (must match `^[A-Z][A-Z0-9_]{2,63}$`, so the lowercase run prefix is converted); `HARNESS_TWENTY_CANARY_VALUE` set to a random 32-byte hex value generated in the job and masked (`::add-mask::`). The value is never printed.
- **Precondition (a) presence in the parent:** the parent compares sha256 of the value it set with sha256 of the value passed to compose, by hash only; neither value is printed. If this cannot prove that the server container received the canary through a normal product or harness route, the row stays gated (UNPROBED, no spec file, X-3). No container exec and no hand reading of container env.
- **Control (b), executed first:** a logic function, executed under `LOCAL`, returns its own non-secret marker (proves the function ran, not `DISABLED`) and reads `process.env.PATH` as a string (the sandbox can read its own environment).
